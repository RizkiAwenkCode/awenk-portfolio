# Awenk Portfolio

## Project rules

- Treat the written specifications in `docs/` as the source of truth.
- Work on one approved section at a time.
- Before implementation, explain the files and changes planned.
- After implementation, verify the result and stop for review.
- Never invent facts, metrics, outcomes, links, or assets. Keep missing information as explicit placeholders.
- Do not install dependencies, deploy, or publish without approval.
- Record approved changes in `docs/decisions.md`.
- Keep translated content separate from UI components and preserve the current section when switching language.
- Mobile layout is not approved; propose it separately before implementation.
